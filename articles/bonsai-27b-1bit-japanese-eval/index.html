3.5GB で 27B が動く

PrismML が 7/14 に出した Bonsai 27B が話題になっています。Qwen3.6-27B の重みを 1-bit（{-1, +1}）まで削って 3.5GB にしたモデルで、公称は「FP16 比 89.5% のベンチ維持」。
27B がスマホに載る、が売り文句です。

自分のローカルマシンでは、エージェントメモリのために、日本語の記憶テキストをローカル LLM で構造化抽出しています（登場人物・感情の座標・活動種別などを JSON で抜く用途です）。今は Qwen3.5 の 9B を使っていて、RTX 5070 の 12GB VRAM にちょうど収まっています。27B は普通の 4bit 量子化でも 16GB 超えで載りません。それが 3.5GB で来たので、乗り換えできるか試したくなりました。

結論を先に書きます。英語では公称に近い実力がありました。日本語読解では性能がqwen3.5:9bより低いです。

最初の測定: 採用へ傾く

手持ちの評価セット（英語 18 問、entity 抽出の F1 で採点）で測りました。

entity 抽出 F1 VRAM 18+16 case 所要
qwen3.5:9b 0.830 5.6GB 46 秒
Bonsai 27B (1-bit) 0.878 5.4GB 47 秒

9B と同じメモリ・同じ速度で 27B が動き、スコアは過去の測定の揺らぎ幅（±0.03）を超えて上。数字だけ見れば乗り換え成立でした。

ただ、18 問は少ないですし、評価が英語のみで、実運用は日本語です。採用を保留して、評価セットを作り直しました。

測り直したら反転した

日英混合の 120 case に拡張しました。追加分は日本語を過半にして、書き込み側のタスク（感情の座標 = VAD の抽出、活動種別の分類）も新設しています。gold ラベルは別ベンダーの LLM に盲検で付けさせて突き合わせ、割れたところだけ人間が裁定しました。

Bonsai 27B qwen3.5:9b
entity 抽出 F1（当初の英語 18 問） 0.898 0.830
entity 抽出 F1（追加分、日本語過半） 0.347 0.383
主観フィルタ精度（追加の境界ケース） 0.750 0.833
活動種別の分類精度 0.633 0.833

最初に見えた優位は消えました。

壊れ方が言語で異なる

感情の覚醒度（arousal）の正負を当てるタスクで、言語別にこうなりました。

arousal 符号の正答率 日本語 英語
Bonsai 27B 0.333 0.900
qwen3.5:9b 0.778 0.900

英語では 9B と同等に動きます。日本語では 3 回に 2 回外します。二択なので当てずっぽう未満です。活動種別の分類も日本語だけ 0.500 まで落ち、入力文の丸写し（要約せずにそのまま返す）も日本語で増えました。

つまり 1-bit 圧縮は能力を一様に 89.5% へ削るのではなく、学習データ上の少数派言語の繊細な読解から先に削っているように見えます。「FP16 比 89.5% retention」は英語ベンチの平均としては嘘ではないのでしょう。ただ、その平均は日本語の感情読解みたいな裾の能力について何も保証していません。

試す人向けの落とし穴 2 つ

  • stock Ollama では動きません。1-bit の量子化形式（Q1_0）は llama.cpp 本家にはマージ済みですが、Ollama 同梱の ggml が未対応です。llama.cpp の llama-server を直接立てるのが早いです（公式リリースの CUDA ビルドで動きました）
  • thinking を切らないと structured output が壊れます。Bonsai は reasoning 型で、放っておくと考え事だけで max_tokens を使い切り、肝心の JSON が空になります。chat_template_kwargs: {"enable_thinking": false} で解決します。うちの評価では、これに気づく前のスコアが F1 0.317、切った後が 0.878 でした

まとめ

英語だけで使うなら、3.5GB で 27B 相当が動くのは本物のようです。日本語の、とくに感情やニュアンスの読解が要る用途では、現時点の 1-bit はまだ渡れない橋でした。

今後のため覚えておきたいのは、小さいベンチの好成績で採用を決めない、公称値でなく、自分の言語・自分のタスクで測ること、です。

とはいえこれで確定という話でもないと思いますので、他の方の調査知見も知りたいところです。

追記（同日）: 巻き添えで現行モデルの座も落ちた

この評価をしていて気づいたことがもう 1 つあります。現行の qwen3.5:9b を採用したときの比較相手は、実効 4B 級のモデルだけでした。つまり「格下にしか勝っていない」状態で採用していたわけです。

そこで同じ 120 case で、同格上位の gemma-4-12b-it QAT q4_0（Google 公式の量子化前提学習版、7.2GB）と当ててみました。

gemma-4-12b QAT qwen3.5:9b
日本語 arousal 符号の正答率 1.000 0.778
日本語 entity 抽出 F1 0.424 0.240
主観フィルタ精度（全体） 0.925 0.900

主要 18 指標中 17 で現行を上回り、日本語ではクラウドモデル（Claude Sonnet）にほぼ並びました。その日のうちにデフォルトを乗り換えました。

QAT（quantization-aware training、量子化を前提に学習しておく方式）の q4 は、後付けの量子化とは別物の日本語品質でした。Bonsai の検証のために作った評価セットが、そのまま現行モデルの座も落とした形です。教訓に 1 つ追加です。モデルを採用するときは、何に勝ったのかを記録しておくこと。
